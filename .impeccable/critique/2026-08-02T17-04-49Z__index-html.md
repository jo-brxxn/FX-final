## Design Specificity Verdict

**Split verdict: the data layers are genuinely product-specific, the shell is generic — and a chunk of what the static scanner flags is actually deliberate, previously-agreed design language, not a defect.**

**LLM assessment (A):** The Set-ups triage board (Bullish/Neutral/Bearish as literal columns), the COT report card (net long/short split, "3y %ile", CFTC provenance), the calendar's live now-line, and the bias/score system are all genuinely bespoke — none of that could be lifted into an unrelated SaaS product unchanged. The header, tab bar, generic card chrome, and Overview card, by contrast, are interchangeable with any analytics dashboard. One element is specific to the *wrong* product: the globe hero's "THRUST" slider, "FUEL 100%", and "SCAN POSITION 79.2°W" are flight-sim telemetry with no market meaning — invented numbers in a tool whose core value is data trust.

**Deterministic scan (B):** the CLI scan (`detect.mjs`) found 21 static findings, and a live browser-injected pass found 141–307 findings per view (Dashboard/FX-detail/Calendar), dominated by `undersized-ui-text` (69–150/view), `tiny-text` (88/view), `gpt-thin-border-wide-shadow` (37/view), and `ai-color-palette` "cyan neon on dark" (12/view).

**Where both agree (high-confidence, cross-validated):** tiny/undersized text, thin-border-plus-shadow card chrome, and a neon-leaning color palette were all found *independently* by the LLM review and the mechanical detector — that convergence is the strongest signal in this report.

**Detector-only find worth acting on:** `text-occlusion` — the globe HUD's "TRACKING" label is reported 100% covered by an overlapping SVG element. That's a literal violation of this project's own documented rule that elements must never overlap to the point of being unreadable.

**False positives relative to this project's own history (not real defects):** `side-tab` (9 hits) is the app's foundational, repeatedly-reaffirmed bias-indication convention (left border stripe only, no background tint) — not slop, it's the design system. `bounce-easing` on `.score-pop`, the `radial-halo`/`dark-glow` on `.aurora-a`/`.glow-*`, and `codex-grid-background` on `.intro-grid` are all animations/effects that were deliberately added, removed, and re-added on explicit user request in earlier rounds — the detector can't know that history. `pulsing-dot` (4/view) likewise matches intentionally-restored infinite pulses (inbox badge, live dot, notify banners). `overused-font` flagging `Arial` is likely a detector labeling mismatch — Arial isn't on the rule's own "AI-slop font" list.

## Overall Impression

The app is more product-specific and further along than a fresh critique of "generic AI-generated dashboard" would suggest — the data views (COT, Set-ups, Calendar) show real domain expertise, and the provenance/honesty copy is genuinely best-in-class. But the visual execution hasn't caught up to the content: there's no coherent type scale, color is doing double duty as both "this is positive" and "this is clickable," and the accessibility floor is close to zero. The single biggest opportunity is also the cheapest to fix: a handful of token-level changes (type scale, color separation, card footer) would close most of the visible gap to your reference images without touching any functionality.

## What's Working

1. **Data-provenance honesty is best-in-class.** The COT card's meta line — report date, age, publication date, source, methodology, and a staleness warning in one sentence — is the kind of thing most commercial terminals hide. Worth propagating to every card.
2. **The Set-ups triage board** is the most product-specific composition in the app — Bullish/Neutral/Bearish as literal columns with colored rails is instantly scannable and structurally correct for what it does.
3. **The copy is written by a domain expert**, not a copywriter — inline legends like "blue = Long · red = Short · sorted by long share" teach without a tooltip.

## Priority Issues

**[P0] The primary manual action in the product is invisible**
- **Why it matters:** Setting a bias — the core thing a user *does* here — requires a 450ms long-press with only a `title` tooltip as the affordance, which never fires on touch. Dashboard edit mode needs a 5-second hold. A user who doesn't already know the gesture, especially on mobile, cannot set a bias, reorder, or delete anything.
- **Fix:** Add a persistent low-opacity `⋯` handle in each card/indicator header that opens the same bias popover on tap; keep long-press as the accelerator, not the only path. Cut dashboard edit mode toward ~700ms and add an explicit "Edit layout" entry in the existing header menu.
- **Suggested command:** `/impeccable clarify`

**[P1] Typography has no coherent scale**
- **Why it matters:** 16 distinct font sizes on one page, 101 text nodes under 11px (down to 8px), and card titles that are 23px sentence-case on FX detail but 13px uppercase-tracked on Dashboard — the same component styled two different ways. Independently confirmed by the detector: `undersized-ui-text` fired 69–150 times per view, `tiny-text` 88 times. This is the single biggest measurable gap to your reference images.
- **Fix:** Define a 6-step scale as CSS custom properties (micro/label/body/title/lead/hero), delete ad-hoc sizes, and unify every module header (rubric cards, Overview, dashboard widgets, page titles) onto one small-uppercase-tracked title token, matching what the Dashboard cards already do correctly.
- **Suggested command:** `/impeccable typeset`

**[P1] Color carries two incompatible jobs at once**
- **Why it matters:** `--green` and `--blue` are the identical hex (`#5fa8ed`) — bullish scores, the logo, the active tab, every ⓘ icon, and every link are all one color, so "this value is positive" and "this is clickable" are visually the same signal. The detector independently flagged `ai-color-palette` ("cyan neon on dark") 12 times per view and `gpt-thin-border-wide-shadow` (thin border + wide glow, matching the card-chrome pattern) 37 times per view. Separately, the aurora background wash means the neutral near-black you specified in `:root` never actually renders on screen.
- **Fix:** Give bullish its own hue distinct from interactive blue, flatten the saturated COT/net-flow bars to a single flat tone, and turn down the aurora until the measured page background matches your own token in every corner.
- **Suggested command:** `/impeccable colorize`

**[P1] Accessibility floor is close to zero**
- **Why it matters:** Measured: 23 `outline:none` declarations against 1 restoration, 0 `:focus-visible` rules, 0 `tabindex` attributes, 107 `div`/`span`/`tr` elements with `onclick` and no role, 0 `aria-label` across 375 interactive elements, and 81 touch targets under 32px. The detector independently caught a concrete WCAG failure (white text on `#ef5350`, 3.5:1 contrast where 4.5:1 is required) and a genuine overlap bug — the globe HUD's "TRACKING" label is reported 100% covered by an overlapping element, which directly violates this project's own "elements must never overlap to the point of being unreadable" rule.
- **Fix:** One global `:focus-visible` ring on all interactive elements, convert clickable `div`s to real buttons or add `role="button" tabindex="0"`, `aria-label` on icon-only buttons, raise touch targets to ≥32px, fix the specific white-on-red contrast pair, and fix the TRACKING label overlap.
- **Suggested command:** `/impeccable harden`

**[P2] The app spends its most valuable pixels on its least valuable content**
- **Why it matters:** The Overview card uses ~130px to show 6 numbers that are repeated in full context 300px below it, with a large empty gutter inside each tile — the code already computes a one-line summary (`summarizeRub`) that the tile isn't rendering. The Interest Rates card is forced to 415px tall to match its sibling, showing 3 rows of "–" and ~200px of empty space. Row height runs ~37px versus a much tighter feel in your references. Four full-width 60px price cards occupy the top of the dashboard for what could fit in a slim status strip.
- **Fix:** Render the existing summary text into the Overview tiles (or remove the card), add a closing "score" footer bar to rubric cards so they stop stretching to match siblings, tighten row height, and move top-of-dashboard prices into a compact strip.
- **Suggested command:** `/impeccable layout`

## Persona Red Flags

**Alex (Power User):** Can't switch tabs by keyboard (0 tabindex, no hotkeys beyond `/` for search). Setting six rubric biases on one asset means six 450ms long-presses. The ▲▼ reorder buttons sit 4px from a destructive × at 21×25px — guaranteed mis-clicks at speed. Dashboard edit mode's 5-second hold means he'll assume the feature doesn't exist.

**Sam (Accessibility-dependent):** Tabbing produces no visible focus almost anywhere (0 `:focus-visible`). 107 clickable `div`s are unreachable by keyboard and announce nothing. Zero `aria-label`s across 375 interactive elements — on mobile the header collapses to six icon-only buttons with no accessible name at all. Bias is conveyed by color + glyph + a 4px border, all invisible to him; the ⓘ button that unlocks every explanation is 13×13px with no label.

**Casey (Mobile):** Header + tab bar eat 24% of an 844px viewport before any data appears. The tab bar itself overflows with no scroll affordance — "Calendar" clips mid-word and "Notes" is entirely off-screen. The FX-detail Overview card alone fills the remaining viewport, so she scrolls a full screen of redundant labels before reaching a real indicator. Every management action is a long-press, which on a phone competes with scroll-start and text selection, and the explanatory tooltips never render on touch.

## Minor Observations

- `.rub-card` hardcodes a raw hex (`#2c4f7c`) outside the token system.
- Rubric card headers use a *lighter* background than the card body — the inverse of your reference images.
- The card title is a styled `<input>`, so a stray click can start a rename; also explains why it renders oversized relative to everything else.
- Set-ups rows mix three different pill styles plus a star icon — four visual languages in one row.
- Calendar rows show a bare "–" for both Actual and Forecast on every future event; a muted "awaiting release" label would read better.
- "GER 100" and "DAX" both appear in the Set-ups neutral column — possible duplicate.
- No `prefers-color-scheme`/light theme at all — a hard blocker in a bright room. `prefers-reduced-motion` is well-covered by contrast (17 places).
- The Help modal force-opens on every fresh profile, before the product has shown a single number.
